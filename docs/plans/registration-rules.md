# 参加登録のルール 実装計画

> STEP 4 の解答例です。plan mode で出た計画を、受け入れ条件と照合して直したものです。

仕様: docs/specs/registration-rules.md

1. registrations に user_id と event_id の組み合わせの一意インデックスを追加する。既存の重複は削除せず、重複があればマイグレーションを止めて知らせる（AC-3）
2. Registration に同じ user と event の組み合わせの一意性バリデーションを追加する（AC-3）
3. Event に、登録者数が定員に達しているかを返すメソッドと、いま申込を受け付けているか（締切時刻まで、締切がなければ開催日時まで）を返すメソッドを追加する（AC-1, AC-2）
4. 参加登録の処理をモデルにまとめる。イベントの行をロックしたうえで、満席・締切後なら理由を返して登録しない。キャンセル済みの登録があれば、新しい行を作らずにその行を登録済みに戻す（AC-1, AC-2, AC-3）
5. RegistrationsController#create は 4 の処理を呼び、登録できなかったときは「満席です」または「申込は締め切りました」を表示してイベント詳細に戻す（AC-1, AC-2）
6. キャンセルは今の処理のまま、締切後も行えることを確かめる（AC-4）
7. マイページは登録済みとキャンセル済みの両方を表示し、キャンセル済みには「キャンセル済み」と添える。登録は1人1イベント1件なので、同じイベントが2件出ることはない（AC-5）
8. モデルスペックとシステムスペックを追加し、bundle exec rspec がすべて通ることを確かめる
